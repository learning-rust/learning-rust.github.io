## Why `Option` and `Result`?

Many programming languages use exceptions to handle errors and `null`\ `nil`\ `undefined` types to handle missing values. Historically, this decision has led to severe runtime issues (such as null pointer exceptions) and security vulnerabilities (sensitive data leakages, through error traces and exceptions). Rust skip both and provide two special generic enums defined in its standard library to prevent these issues.

1. `Option`
   - Represents the potential absence of a value.
   - The value can have either some value/`Some` or no value/`None`.
   ```rust
   enum Option<T> {
       Some(T),
       None,
   }
   ```
2. `Result`
   - Represents the outcome of a fallible operation.
   - The result can have either success/`Ok` or failure/`Err`.
   ```rust
   enum Result<T, E> {
       Ok(T),
       Err(E),
   }
   ```

> [!recap]
> As both `Option` and `Result` are in the [preludes](/docs/the-pillars-of-compilation-and-rust-std/#rust-preludes) we can use them directly without using namespaces in the code.

## Basic Usages of `Option`

### Optional Types

```rust
struct Task {
  title: String,
  assignee: Option<Person>,
}
// A task might not be assigned to anybody yet. So, its assignee is optional
// 💡 Instead of `Person`, use `Option<Person>`

struct Person {
    name: String,
    company_name: Option<String>,
}
// A person might not represent any company. So, the company_name is optional
// 💡 Instead of `String`, use `Option<String>`
```

### With `match`

```rust
fn handle_some_none(i: Option<i32>) {
    match i {
        Some(x) => println!("{x}"),
        None => println!("{:?}", i),
    }
}

fn handle_some(i: Option<i32>) {
    match i {
        Some(x) => println!("{x}"),
        _ => (), // skip None via default
    }
}

fn main() {
    handle_some_none(Some(6)); // 6
    handle_some_none(None);    // None

    handle_some(Some(7)); // 7
    handle_some(None);    // This prints nothing
}

// ⭐️ Inside a match Option, None should be handled.
```

```rust
fn handle_some_none(i: Option<i32>) {
    match i {
        Some(x) if x > 5 => println!("Greater than 5"),
        Some(x) if x > 0 => println!("{x}"),
        None | _ => println!("{:?}", i),
    }
}

fn main() {
    handle_some_none(Some(6)); // Greater than 5
    handle_some_none(Some(5)); // 5

    handle_some_none(Some(-5)); // Some(-5)
    handle_some_none(None);     // None
}
```

### With `if let`

```rust
fn handle_some_none(i: Option<i32>) {
    if let Some(x) = i {
        println!("{x}");
    } else {
        println!("{:?}", i);
    }
}

fn handle_some(i: Option<i32>) {
    if let Some(x) = i {
        println!("{x}");
    }
}

fn main() {
    handle_some_none(Some(6)); // 6
    handle_some_none(None);    // None

    handle_some(Some(7)); // 7
    handle_some(None);    // This prints nothing
}
```

```rust
fn handle_some_none(i: Option<i32>) {
    if let Some(x) = i && x > 5 {
        println!("Greater than 5");
    } else {
        println!("{:?}", i);
    }
    // ⭐️ Can't access `x` in `else if` or `else`
}

fn main() {
    handle_some_none(Some(6)); // Greater than 5
    handle_some_none(Some(5)); // Some(5)
    handle_some_none(None);    // None
}
```

### With `let else`

```rust
fn handle_some_none_i32(i: Option<i32>) -> i32 {
    let Some(x) = i else {
        return 0; // if None, x = 0;
    };

    x
    // 👨‍🏫 Same functionality can be written via `i.unwrap_or(0)`
}

fn handle_some_none(i: Option<i32>) {
    let Some(x) = i else {
        println!("0");
        return;
    };

    println!("{x}");
}

fn main() {
    println!("{}", handle_some_none_i32(Some(10))); // 10
    println!("{}", handle_some_none_i32(None));     // 0

    handle_some_none(Some(10)); // 10
    handle_some_none(None);     // 0
}
```

### Nullable Pointer Types

```rust
struct Node {
    value: i32,
    next: Option<Box<Node>>,
}
```

> [!tip]
> Rust guarantees to optimize types such as `Option<&T>`, `Option<Box<T>>`, and `Option<NonNull<T>>` has the same size, alignment, and function call ABI as `T`. This is called the [null pointer optimization or NPO](https://doc.rust-lang.org/std/option/index.html#representation). Because there are no null pointers in safe Rust, the pointer types should point to a valid location. This gives you null safety with no additional runtime cost.

## Basic usages of `Result`

### Result Types

```rust
struct Config {
    filename: String,
    contents: Result<String, std::io::Error>,
}
// Reading a file can fail. So, its contents are a Result.
// 💡 Instead of `String`, use `Result<String, std::io::Error>`

struct User {
    name: String,
    age: Result<u8, std::num::ParseIntError>,
}
// Parsing user input can fail.
// 💡 Instead of `u8`, use `Result<u8, std::num::ParseIntError>`
```

### With `match`

```rust
fn handle_ok_err(r: Result<i32, &str>) {
    match r {
        Ok(x) => println!("{x}"),
        Err(e) => println!("{e}"),
    }
}

fn handle_ok(r: Result<i32, &str>) {
    match r {
        Ok(x) => println!("{x}"),
        _ => (), // skip Err via default
    }
}

fn main() {
    handle_ok_err(Ok(6)); // 6
    handle_ok_err(Err("No value")); // No value

    handle_ok(Ok(7)); // 7
    handle_ok(Err("No value")); // This prints nothing
}

// ⭐️ Inside a match Result, Err should be handled.
```

```rust
fn handle_ok_err(r: Result<i32, &str>) {
    match r {
        Ok(x) if x > 5 => println!("Greater than 5"),
        Ok(x) if x > 0 => println!("{x}"),
        Err(_) | _ => println!("{:?}", r),
    }
}

fn main() {
    handle_ok_err(Ok(6));   // Greater than 5
    handle_ok_err(Ok(5));   // 5

    handle_ok_err(Ok(-5));  // Ok(-5)
    handle_ok_err(Err("No value")); // Err("No value")
}
```

### With `if let`

```rust
fn handle_ok_err(r: Result<i32, &str>) {
    if let Ok(x) = r {
        println!("{x}");
    } else {
        println!("{:?}", r);
    }
}

fn handle_ok(r: Result<i32, &str>) {
    if let Ok(x) = r {
        println!("{x}");
    }
}

fn main() {
    handle_ok_err(Ok(6));           // 6
    handle_ok_err(Err("No value")); // Err("No value")

    handle_ok(Ok(7));           // 7
    handle_ok(Err("No value")); // This prints nothing
}
```

```rust
fn handle_ok_err(r: Result<i32, &str>) {
    if let Ok(x) = r && x > 5 {
        println!("Greater than 5");
    } else {
        println!("{:?}", r);
    }
}

fn main() {
    handle_ok_err(Ok(6)); // Greater than 5
    handle_ok_err(Ok(5)); // Ok(5)
    handle_ok_err(Err("No value")); // Err("No value")
}   
```

### With `let else`

```rust
fn handle_ok_err_i32(r: Result<i32, &str>) -> i32 {
    let Ok(x) = r else {
        return 0; // if Err, return 0;
    };

    x
    // 👨‍🏫 Same functionality can be written via `r.unwrap_or(0)`
}

fn handle_ok_err(r: Result<i32, &str>) {
    let Ok(x) = r else {
        println!("0");
        return;
    };

    println!("{x}");
}

fn main() {
    println!("{}", handle_ok_err_i32(Ok(10)));          // 10
    println!("{}", handle_ok_err_i32(Err("No value"))); // 0

    handle_ok_err(Ok(10));      // 10
    handle_ok_err(Err("No value")); // 0
}
```

## `is_some()`, `is_none()`, `is_ok()`, `is_err()`

Other than `match`, `if let`, `let else` expressions, Rust provides helper functions to identify the return type directly.

```rust
fn main() {
    let x: Option<i32> = Some(6);
    assert_eq!(x.is_some(), true);
    assert_eq!(x.is_none(), false);

    let y: Result<i8, &str> = Ok(7);
    assert_eq!(y.is_ok(), true);
    assert_eq!(y.is_err(), false);
}
```

## `ok()`, `err()` for Result types

In addition to that, Rust provides `ok()` and `err()` for `Result` types. They convert the `Ok<T>` and `Err<E>` values of a `Result` type to `Option` types.

```rust
fn main() {
    let o: Result<i8, &str> = Ok(8);
    let e: Result<i8, &str> = Err("message");
    
    assert_eq!(o.ok(), Some(8)); // Ok(v) ok = Some(v)
    assert_eq!(e.ok(), None);    // Err(v) ok = None
    
    assert_eq!(o.err(), None);            // Ok(v) err = None
    assert_eq!(e.err(), Some("message")); // Err(v) err = Some(v)
}
```

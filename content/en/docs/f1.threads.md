## Fork-Join Model

In parallel computing, the fork–join model is a way of setting up and executing parallel programs so that execution branches off ("fork") in parallel at designated points in the program, and then "join" (merge) at a subsequent point to resume sequential execution. Parallel sections may fork recursively until a certain task granularity is reached *(See [wikipedia](https://en.wikipedia.org/wiki/Fork–join_model) for more information)*.

![Fork-Join model](/docs/f1.fork-join-model.jpg)

Complex parallel programs can be written using recursion, merging each branch at different points as follows.

## Spawn a Thread

> [!tip]
> The term `Spawning` emphasizes that a new thread (or process) branches off from an existing parent and runs independently. The term `Spawn` is quite common with other programming languages as well.

### Without join

> [!note]
> 👨‍🏫 This is not the correct way! \
> But, we can block the main thread to guarantee that it waits long enough until the spawned thread completes.

```rust
use std::thread;

fn main() {
    let _ = thread::spawn(|| {
        println!("Hello, world!");
    });

    // thread::sleep(std::time::Duration::from_secs(1));
}
```

> [!important]
> - For this, the Rust playground shows nothing as output, but if we run locally, we will sometimes see `Hello, world!` as output.
> - 👨‍🏫 Try to uncomment line 8 to block the main thread for 1 more second. This guarantees we wait long enough for the spawned thread to complete.

### With Join

```rust
use std::thread;

fn main() {
    let handle = thread::spawn(|| {
        println!("Hello, world!");
    });
    handle.join().unwrap();
}

// 👨‍🏫 You will always see `Hello, world!` in standard output, even on the Rust playground.
// `thread::spawn` returns a `JoinHandle`. 
// Running `join()` method on the handle, forces the current thread to wait until the associated thread to finish.
```

Also, `thread::spawn` can be called in nested or recursively.

```rust
use std::thread;

fn main() {
    let handle = thread::spawn(|| {
        println!("outer");

        let inner_handle = thread::spawn(|| {
            println!("inner");
        });
        inner_handle.join().unwrap();
    });
    handle.join().unwrap();
}
```

```rust
use std::thread;

fn countdown(n: u32) {
    if n == 0 {
        println!("Done!");
        return;
    }

    println!("Count: {}", n);

    // Spawn a new thread to recursively calls countdown
    let handle = thread::spawn(move || {
        countdown(n - 1);
    });

    handle.join().unwrap();
}

fn main() {
    countdown(3);
}
```

### Outputs

```rust
use std::thread;

fn main() {
    let handle = thread::spawn(|| "Hello, world!");
    match handle.join() {
        Ok(v) => println!("{v}"),
        Err(e) => println!("{:?}", e),
    };
}
// 👨‍🏫 If the associated thread panics, an `Err` is returned with the parameter given to `panic!`
```


### Inputs

> [!important]
> - Since the new thread runs in parallel, the stack frame containing data that passes to the new thread might not outlive till the new thread finishes. Therefore, we have to use a `move` closure while passing any non-`'static` data from the parent thread.
> - However, we can access `'static` data belongs to parent's stack frame even from the newly spawned threads without moving them or using a move closure.

```rust
use std::thread;

const DATA: &str = "Hello, world!"; // 'static str

fn main() {
    let handle1 = thread::spawn(|| {
        println!("{DATA}");
    });

    let data: u8 = 255;
    let handle2 = thread::spawn(move || {
        println!("{data}");
    });

    let data = vec![1, 2, 3];
    let handle3 = thread::spawn(move || {
        println!("{:?}", data);
    });

    handle1.join().unwrap();
    handle2.join().unwrap();
    handle3.join().unwrap();
}

// 👨‍🏫 The order of outputs may vary each time you run it locally.
//    However, in the Rust playground, you will see this same order every time.
// Hello, world!
// 255
// [1, 2, 3]
```

## Thread ID & Name

> [!tip]
> - `thread::current()` : returns  a `Thread`
> - `handle.thread()` : returns a `&Thread`

### Current Thread

```rust
use std::thread;

fn main() {
    let main = thread::current();
    println!("{:?}: {:?}", main.id(), main.name()); // ThreadId(1): Some("main")

    thread::spawn(|| {
        let current = thread::current();
        println!("{:?}: {:?}", current.id(), current.name()); // ThreadId(2): None

        thread::spawn(|| {
            let current = thread::current();
            println!("{:?}: {:?}", current.id(), current.name()); // ThreadId(3): None
        }).join().unwrap();

    }).join().unwrap();
}

// 👨‍🏫 The order of output:
// ThreadId(1): Some("main")
// ThreadId(2): None
// ThreadId(3): None
```

### Handle's Thread

```rust
use std::thread;

fn main() {
    let main = thread::current();
    println!("{:?}: {:?}", main.id(), main.name()); // ThreadId(1): Some("main")

    let handle = thread::spawn(|| {
        let handle = thread::spawn(|| {});
        let thread = handle.thread();
        println!("{:?}: {:?}", thread.id(), thread.name()); // ThreadId(3): None
        handle.join().unwrap();
    });
    let thread = handle.thread();
    println!("{:?}: {:?}", thread.id(), thread.name()); // ThreadId(2): None
    handle.join().unwrap();
}

// 👨‍🏫 The order of output:
// ThreadId(1): Some("main")
// ThreadId(2): None
// ThreadId(3): None
```

## Thread Builder

> [!important]
> Currently in Rust,
> - All Tier-1 platforms assign 2MB default stack size for spawn threads.
> - There are 2 ways to manually set/ override the stack size of spawn threads,
>   - `RUST_MIN_STACK` environment variable: 
>     - Reads only on program start. Allow setting an integer as the desired stack size(in bytes).
>   - `Builder::stack_size`:
>     - Can override both platform's default stack size and `RUST_MIN_STACK`.
> - However, the stack size of main thread is set by the OS or linker; not by Rust.
>   - Typically, 8MB on Linux and macOS; 1MB on Windows.

```rust
use std::thread;

fn main() {
    let main = thread::current();
    println!("{:?}: {:?}", main.id(), main.name()); // ThreadId(1): Some("main")

    let builder = thread::Builder::new()
        .name("foo".to_string())
        .stack_size(8 * 1024); // in bytes = 8KB

    let handle = builder.spawn(|| {
        let current = thread::current();
        println!("{:?}: {:?}", current.id(), current.name()); // ThreadId(2): Some("foo")
    }).unwrap();

    handle.join().unwrap();
}

// 👨‍🏫 The order of output:
// ThreadId(1): Some("main")
// ThreadId(2): Some("foo")
```

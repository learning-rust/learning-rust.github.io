## `unwrap`

- If an `Option` type has `Some` value or a `Result` type has a `Ok` value,
  - The value inside them passes to the next step.
- If the `Option` type has `None` value or the `Result` type has `Err` value, program panics at runtime.
  - If `Err`, panics with the error message.

### With `Option`

Without using `unwrap`,

```rust
fn handle_some_none(i: Option<i32>) {
    match i {
        Some(x) => println!("{x}"),
        None => panic!(),
    }
}

fn main() {
    handle_some_none(Some(6)); // 6
    handle_some_none(None);    // Crash at runtime
}
```

> [!Caution] Crash at Runtime
> ```
> thread 'main' (123456) panicked at src/main.rs:4:17:
> explicit panic
> ```

With `unwrap`,

```rust
fn handle_some_none(i: Option<i32>) {
    println!("{}", i.unwrap());
}

fn main() {
    handle_some_none(Some(6)); // 6
    handle_some_none(None);    // Crash at runtime
}
```

> [!Caution] Crash at Runtime
> ```
> thread 'main' (123456) panicked at src/main.rs:2:22:
> called `Option::unwrap()` on a `None` value
> ```

### With `Result`

Without using `unwrap`

```rust
fn handle_ok_err(r: Result<i32, &'static str>) {
    match r {
        Ok(x) => println!("{x}"),
        Err(e) => panic!("{}", e),
    }
}

fn main() {
    handle_ok_err(Ok(6));           // 6
    handle_ok_err(Err("No value")); // Crash at runtime
}
```

> [!Caution] Crash at Runtime
> ```
> thread 'main' (123456) panicked at src/main.rs:4:19:
> No value
> ```

With `unwrap`,

```rust
fn handle_ok_err(r: Result<i32, &'static str>) {
    println!("{}", r.unwrap());
}

fn main() {
    handle_ok_err(Ok(6));           // 6
    handle_ok_err(Err("No value")); // Crash at runtime
}
```

> [!Caution] Crash at Runtime
> ```
> thread 'main' (123456) panicked at src/main.rs:2:22:
> called `Result::unwrap()` on an `Err` value: "No value"
> ```

## `expect`

Similar to `unwrap` but can set a custom message for the panics.

### With `Option`

```rust
fn handle_some_none(i: Option<i32>) {
    println!("{}", i.expect("None value on i"));
}

fn main() {
    handle_some_none(Some(6)); // 6
    handle_some_none(None);    // Crash at runtime
}
```

> [!Caution] Crash at Runtime
> ```
> thread 'main' (123456) panicked at src/main.rs:2:22:
> None value on i
> ```

### With `Result`

```rust
fn handle_ok_err(r: Result<i32, &'static str>) {
    println!("{}", r.expect("Error on r"));
}

fn main() {
    handle_ok_err(Ok(6));           // 6
    handle_ok_err(Err("No value")); // Crash at runtime
}
```

> [!Caution] Crash at Runtime
> ```
> thread 'main' (123456) panicked at src/main.rs:2:22:
> Error on r: "No value"
> ```

## `unwrap_err` & `expect_err` for `Result` Types

> [!tip]
> - The opposite case of `unwrap` and `expect`; Panics with `Ok` values, instead `Err`.
> - Usually use with tests.
> - Both print the value inside `Ok` on the error message.

### `unwrap_err`

```rust
fn main() {
    let r: Result<i32, &str> = Ok(8);
    r.unwrap_err();
}
```

> [!Caution] Crash at Runtime
> ```
> thread 'main' (123456) panicked at src/main.rs:3:7:
> called `Result::unwrap_err()` on an `Ok` value: 8
> ```

### `expect_err`

```rust
fn main() {
    let r: Result<i32, &str> = Ok(8);
    r.expect_err("Custom message");
}
```

> [!Caution] Crash at Runtime
> ```
> thread 'main' (123456) panicked at src/main.rs:3:7:
> Custom message: 8
> ```

## `unwrap_or`, `unwrap_or_default` & `unwrap_or_else`
> [!tip]
> - These are bit similar to `unwrap`, If an `Option` type has `Some` value or a `Result` type has a `Ok` value, the value inside them passes to the next step. 
> - But when having `None` or `Err`, the functionalities are a bit different.

### `unwrap_or`

With `None` or `Err`, the value you passes to `unwrap_or` is passing to the next step. But, the data type of the value you pass should match with the data type of the relevant `Some` or `Ok`.

```rust
fn main() {
    let x = 1;

    let a = Some(5);
    let b = None;

    assert_eq!(a.unwrap_or(x), 5);
    assert_eq!(b.unwrap_or(x), 1);

    let c: Result<i32, &str> = Ok(5);
    let d: Result<i32, &str> = Err("No value");

    assert_eq!(c.unwrap_or(x), 5);
    assert_eq!(d.unwrap_or(x), 1);
}
```

### `unwrap_or_default`

With `None` or `Err`, the default value of the data type of the relevant `Some` or `Ok`, is passing to the next step.

```rust
fn main() {
    let a = Some(5);
    let b: Option<i32> = None;

    assert_eq!(a.unwrap_or_default(), 5);
    assert_eq!(b.unwrap_or_default(), 0);

    let c: Result<i32, &str> = Ok(5);
    let d: Result<i32, &str> = Err("No value");

    assert_eq!(c.unwrap_or_default(), 5);
    assert_eq!(d.unwrap_or_default(), 0);
}

```

### `unwrap_or_else`

Similar to `unwrap_or`. The only difference is, instead of passing a value, you have to pass a [closure](/docs/functions/#closures) which returns a value with the same data type of the relevant `Some` or `Ok`.

```rust
fn main() {
    let a = Some(5);
    let b = None;
    let fn_x = || 1;

    assert_eq!(a.unwrap_or_else(fn_x), 5);
    assert_eq!(b.unwrap_or_else(fn_x), 1);

    let c: Result<i32, &str> = Ok(5);
    let d: Result<i32, &str> = Err("No value");
    let fn_y = |_| 1;

    assert_eq!(c.unwrap_or_else(fn_y), 5);
    assert_eq!(d.unwrap_or_else(fn_y), 1);
}
```
